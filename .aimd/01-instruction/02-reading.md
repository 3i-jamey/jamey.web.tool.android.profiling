# 읽기 규칙

작업 중 무엇을 열지 결정하는 규칙이다. 세션 시작 읽기 순서는 루트 `AI.md`가 단일 출처이고, 이 문서는 그 뒤 탐색 단계에 적용한다.

## 탐색 진입점

찾는 것의 유형으로 진입점을 고른다.

| 찾는 것 | 진입점 | 여는 범위 |
|---|---|---|
| 단어·용어의 합의된 의미 | `02-reference/01-dictionary.md` | 해당 행 |
| repo 파일·자산의 위치, 폴더 역할 | `02-reference/02-folder-map.md` | 맵에서 폴더를 좁힌 뒤 그 안만 |
| 이 작업 유형에 적용되는 표준·규약 | `11-standard/` | 해당 작업 유형 문서 전부 — 읽으면 따른다 |
| 구조·용어·배경 서술 | `12-wiki/INDEX.md` → 주제 문서 | 해당 주제 폴더 문서만 |
| 판정·상태(감사·품질) | `12-wiki/INDEX.md` → 주제 판정 문서 | 해당 문서만 |
| 닫힌 결정 여부 | `31-adr/` 제목 훑기 | 해당 파일만 |
| 진행 중 세션 맥락 | `22-runtime/context/yymmdd-nn-{slug}/01-overview.md` → 같은 디렉토리의 번호 문서 | 맡은 작업만 |
| 팀 런타임 상태 | `22-runtime/team/{branch-key}/` | 맡은 팀만 |
| 닫힌 과거 기록 | `32-result/` | 사용자가 지목한 파일만 |

## folder-map 활용

- repo 파일을 찾을 때는 전체 검색 전에 `02-folder-map.md`로 후보 폴더를 좁히고, 그 폴더 안에서만 Glob/Grep 한다.
- 폴더를 열기 전에 맵의 역할 설명으로 그 폴더가 맞는 영역인지 먼저 확인한다.
- 새 파일을 둘 위치는 맵에서 역할이 맞는 폴더로 정하고, 맞는 폴더가 없으면 새 폴더 생성과 맵 갱신을 같은 편집으로 계획한다.
- 맵과 실제 폴더가 다르면 같은 편집에서 맵을 실제에 맞게 고친다.

## 읽는 깊이

- 문서는 필요한 섹션만 연다. 큰 파일은 heading을 먼저 훑고 해당 섹션만 정독한다.
- 같은 정보가 여러 문서에 보이면 dictionary·folder-map 같은 단일 출처 문서를 기준으로 삼는다.
- 기록 계층(`21-plan`·`22-runtime/context`·`32-result`)의 과거 파일은 현재 규칙의 근거로 쓰지 않는다.
